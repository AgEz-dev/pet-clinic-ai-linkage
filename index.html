宠安康 × VetClaw
从挂号到病历的 AI 分诊联动

一套宠物门诊业务系统（Java 全栈），另外单独部署了一个分诊 Agent 服务（Python / RAG），两者通过 HTTP + SSE 协作。 链路是：宠主预约 → 预问诊 → 结构化摘要 → 医生诊前阅读 → 起草病历 → 医生签字出具。 业务数据、权限与审计留在 Java 侧；文本生成与检索在 Agent 侧；两端用同一套事件格式与一个链路 ID 串联，便于排查。

01系统拓扑

浏览器只与 Java 通信（鉴权、限流、审计、持久化全部留在 Java 侧）；Agent 不对外暴露，也不反查业务库 —— 保持单向依赖，避免循环调用。

02已实现的功能

真 token 流式

把上游的 SSE 帧原样转发给浏览器，不做前端假切块。单次提问实测 301 帧到达。

急症优先拦截

规则在入口先识别常见毒物与超范围用药：命中就直接给处置指引，不走模型，本机实测中位 1.48ms。

引用可溯源

检索类回答行内标注知识块编号，前端渲染成角标与折叠汇总，知识详情默认折叠。

预问诊（可选）

宠主预约后可自选做或不做：逐轮对话 → 结构化摘要 → 医生诊前阅读。不做也能正常就诊。

病历起草

只起草叙述性内容（主诉 / 建议查体清单 / 医嘱草稿）；确诊字段不输出，由医生填写。

失败不扩散

Agent 不可用时依次退到内置网关、再到固定文案，三级降级，HTTP 始终 200；业务动作不依赖 AI。

03工程约束

涉及医疗场景，下面几条在实现里做了约束，并各自有对应测试。

约束落地方式
不越执业边界草稿输出白名单不含 diagnosis；模型即使输出该字段也被丢弃；命中「确诊 / 诊断为」等措辞的文本整段剔除（Agent 侧 + Java 侧双层）
归属校验前置宠主仅本人预约、医生仅接诊单、管理员可读 —— 校验发生在一切读写之前，越权一律 403
查看即审计医生每次读取预问诊、每次请求起草都写审计；越权尝试同样留痕；审计写入失败只告警，不阻断业务
用量护栏每用户 10 次/分钟滑动窗口（覆盖问答 / 预问诊 / 起草三链路）+ 日配额 50 次；超限 429 并给明确文案
输出有上界单次补全 max_tokens=800（贯穿三条模型链路），输入侧问题 ≤1000 字并限多轮上下文轮数
上下文不串会话标识 conversation_id 贯穿：多轮上下文按会话隔离，无宠物会话不再共享同一个池
草稿不等于病历起草接口不写任何表；草稿只是预填表单，医生核对修改后点「出具」才落库

技术构成

  • 业务端：Spring Boot 2.7 · MyBatis-Plus · MySQL 8 · JWT · SSE
  • 前端：Vue 3 · Vite · Element Plus
  • Agent：FastAPI · ReAct 循环引擎（可选 LangGraph）· bge-small-zh 与 BM25 混合召回（RRF 融合）
  • 工程：先定事件帧与链路 ID 再做实现 · 单元测试 / 集成测试 / 本机端到端各一层 · CI 门禁
